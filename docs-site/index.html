Three convergent products run on one platform: UAIP Core (agent platform + Telescope UX), BaseBench-Meta (metacognitive reliability benchmark), and QuestionForge (stakeholder discovery council). The backend is consolidated from 7 legacy microservices into 2 Bun/Elysia runtimes (navratna-core :3001, navratna-gateway :3002) via the FeatureFactory pattern.

Project Story

Navratna began on April 9, 2025 as a weekend prototype — a "council of nicea": an LLM debate feature on a Vite + React + shadcn stack. Over ~14 months it evolved into a sovereign, multi-agent cognitive operating system.

System Architecture

All traffic flows through the nginx API gateway (:8081) which validates JWT via auth_request and forwards identity headers. Two consolidated Bun/Elysia services compose domain "Features" via the FeatureFactory. Legacy service directories are thin runners re-exporting canonical shared packages.

FeatureFactory pattern — "symphony or a single note"

Every domain exports a Feature object (initialize / routes / events / websocket / shutdown). Consolidated services register features; legacy services run the same feature standalone. Runtime-toggleable via FEATURE_* env vars.

Decision Log

Architectural decisions captured from the production-ready, Layer-C, and table-stakes plans.

D1 · FeatureFactory / "MIDI" pattern
Every domain is a self-contained Feature. navratna-core/gateway are pure compositions with zero business logic. Legacy services run the same Feature standalone.
"work in a symphony or as a single note, or like MIDI through different instruments"
D2 · @uaip/shared-services is the single source of truth
Subpar duplicate copies of PersonaService / DiscussionService in service directories were deleted. Domain logic lives only in canonical shared packages with sub-path exports.
D3 · Consolidate 7 services → 2 runtimes
navratna-core (:3001) + navratna-gateway (:3002) are the primary runtime (~95–97% route parity). Legacy dirs reduced to thin runners. Single-owner v3 posture.
D4 · Fail-closed auth on all write paths
No 'system' or 'anonymous' fallbacks. Missing x-user-id on state-changing endpoints fails closed. (E6 critical finding.)
D5 · Per-package tsconfig.build.json, never big-bang
TS6 migration done one package at a time, verified after each. @uaip/source condition is the dev-resolution safety net, completed before any paths removal.
D6 · Storage split for lineage (hard rule)
PostgreSQL = authoritative event log + outbox (system of record). Neo4j = async projection for traversal (never transactional). Qdrant = vectors only.
D7 · No Express, no TypeORM, no RabbitMQ
Elysia is the HTTP framework, Drizzle + pg Pool the data layer, BullMQ-on-Redis the event bus. No fallbacks, no feature flags as architecture — rollback = git revert.
D8 · Gap F = Verified Autonomy Loop (the wedge)
Reverse-impact + belief quarantine over an agent lineage control plane. Closing table-stakes is admission criteria; the Verified Autonomy Loop is the winning move. Productizes existing engine primitives only — does not touch the cognitive engine.
D9 · snake_case filenames
All navratna filenames use snake_case (agent_routes.ts, feature_factory.ts). No inline types — extract to @uaip/types or local types.ts.
